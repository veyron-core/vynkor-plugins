## 3. Известная проблема: sherpa под супервайзером (supervised-stall)

**Симптом.** Первый локальный sherpa-экшен грузит модель (RSS→160 MB, CPU на
загрузке), затем инференс никогда не завершается; все потоки futex-parked,
0% CPU. Ответ вызывающему не уходит вовсе — даже для мгновенных отказов
(несуществующий peer). Воспроизводится и в standalone `tts` ⇒ **не регрессия
мерджа speech**. Вне ядра тот же бинарник/env/rlimit — TTFA 80–100 мс.

Полная матрица отсечений — в `plugins/speech/ROADMAP.md`.

### Найдено в ходе бисекта (важно для ядра!)

Инструментарий: ветка `debug/sherpa-supervised-stall` (vynkor) — env-
киллсвитчи `VYN_DEBUG_SKIP_CGROUP=1` / `VYN_DEBUG_SKIP_RLIMITS=1` на
процессе ядра + зеркало stderr ребёнка в kernel.log (`[plugin-stderr]`).

1. **Баг NPROC-фолбэка (подтверждён, отдельный фикс).** Если cgroup-join не
   выполнен, `apply_resource_limits` ставит `RLIMIT_NPROC = max_procs`
   (дефолт 64). NPROC считает потоки **всех процессов юзера** — десктоп-сессия
   превышает 64 мгновенно ⇒ `pthread_create → EAGAIN` ⇒ tokio паникует
   `OS can't spawn worker thread`. Любой thread-heavy плагин ломается. Фикс:
   не ставить NPROC из max_procs (или считать иначе / поднять дефолт).
2. **RLIMIT_AS 512M (дефолт) мал для ONNX-плагинов**: модель не аллоцируется.
   Для tts/speech нужно ≥1536M (рекомендация уже в их README), но даже 4096M
   не лечит пункт 3.
3. **Потеря ответа на обратной ноге (главная загадка, открыта).** Зеркало
   stderr показало: хендлер завершается мгновенно (`time-to-first-audio: 0 ms`
   на тёплом движке), чанки уходят, но `ActionResponse` не доходит до
   вызывающего — при том что db_* через того же агента ходят нормально.
   Исключены: rlimits (skip — висит), cgroup (skip — висит), action_id
   дубликаты (UUID — висит), sandbox/seccomp/cwd/пайпы/число потоков ONNX.
   **Следующий шаг:** `strace -f` на пару (процесс tts ↔ ядро) во время вызова
   — увидеть, уходит ли `write()` ответа и что делает ядро дальше; затем
   читать reply-лег `src/ipc/protocol.rs` (pending-реестр: поиск по
   internal_id/action_id, ветка `ActionResponse`) в сравнении db vs tts.

### Workaround
Облачные провайдеры (`openai`/`elevenlabs`) не трогают sherpa и работают под
ядром. Локальный голос — после фикса апстрима или dev-ядро без капов.
